# 5.1 ทดสอบระบบ Authentication and Authorization (Backend — Laravel)

เอกสารนี้อธิบายกรณีทดสอบหลักสำหรับการยืนยันตัวตนและสิทธิ์บน **เว็บ backend (Blade)** เช่น การลงทะเบียนผู้จัดการ การเข้าสู่ระบบ และ redirect ตามบทบาท  
*(ฟอร์ม Sales บางส่วนอยู่ที่ SvelteKit — ดู `flow-crm-frontend/docs/test-cases-auth.md`)*

---

## 5.1.1 ทดลองการลงทะเบียน (ผู้จัดการองค์กร — `/register`)

ฟอร์มบังคับ: **ชื่อ–นามสกุล** (อย่างน้อยสองคำ), **อีเมล**, **รหัสผ่าน + ยืนยัน**, **ชื่อองค์กร**, **ขนาดองค์กร**  
ไม่มีฟิลด์เบอร์โทร / รูปโปรไฟล์ในขั้นตอนลงทะเบียนนี้

**ตารางที่ 5.1 — กรณีทดสอบการลงทะเบียนผู้จัดการ**

| กรณีทดสอบ | เงื่อนไขการทดสอบ | ผลการทดสอบที่คาดหวัง | หมายเหตุ |
|-----------|------------------|----------------------|----------|
| TC-B1.1 | ไม่กรอกข้อมูลใดๆ แล้วส่งฟอร์ม | เบราว์เซอร์หรือเซิร์ฟเวอร์แสดงให้กรอกข้อมูลที่จำเป็น | HTML5 `required` / validation |
| TC-B1.2 | กรอกเฉพาะชื่อ–นามสกุล | ไม่สามารถลงทะเบียนสำเร็จ — แจ้งให้กรอกฟิลด์ที่ขาด | |
| TC-B1.3 | กรอกเฉพาะอีเมลและรหัสผ่าน (ไม่มีชื่อองค์กร / ขนาด) | ไม่สำเร็จ — แจ้งเตือนฟิลด์องค์กร | |
| TC-B1.4 | กรอกครบยกเว้นรหัสผ่านไม่ตรงกับยืนยัน | ไม่สำเร็จ — แจ้งรหัสผ่านไม่ตรงกัน | `password` confirmed |
| TC-B1.5 | กรอกครบถ้วนด้วยอีเมลที่ยังไม่เคยใช้ | ลงทะเบียนสำเร็จ — redirect ไปหน้าตั้งค่า N8n / integrations | `integrations.n8n.setup` |
| TC-B1.6 | กรอกครบแต่ใช้อีเมลที่ลงทะเบียนแล้ว | ไม่สำเร็จ — แจ้งอีเมลซ้ำ | `unique:users,email` |

---

## 5.1.2 ทดลองการเข้าสู่ระบบ (`/login`)

ใช้ **อีเมล + รหัสผ่าน** (ไม่มีช่องเบอร์โทรในฟอร์ม login)

**ตารางที่ 5.2 — กรณีทดสอบการเข้าสู่ระบบ**

| กรณีทดสอบ | เงื่อนไขการทดสอบ | ผลการทดสอบที่คาดหวัง | หมายเหตุ |
|-----------|------------------|----------------------|----------|
| TC-B2.1 | ไม่กรอกอีเมลและรหัสผ่าน | แสดงแจ้งเตือนให้กรอกข้อมูล | `required` |
| TC-B2.2 | กรอกเฉพาะอีเมล | แสดงแจ้งเตือนให้กรอกรหัสผ่าน | |
| TC-B2.3 | กรอกเฉพาะรหัสผ่าน | แสดงแจ้งเตือนให้กรอกอีเมล | |
| TC-B2.4 | กรอกอีเมลและรหัสผ่านถูกต้องของบัญชีที่ใช้งานได้ | เข้าสู่ระบบสำเร็จ — redirect ตามบทบาท (เช่น Manager → dashboard, Sales → แอป frontend ตาม `SALES_APP_URL`) | |

### 5.1.3 การอนุญาต (Authorization) — ย่อ

| กรณีทดสอบ | เงื่อนไข | ผลที่คาดหวัง |
|-----------|----------|--------------|
| TC-B3.1 | Sales เข้าสู่ระบบแล้วเรียกเฉพาะ route ที่อนุญาต | เข้าถึงได้ตามสิทธิ์ |
| TC-B3.2 | Sales พยายามเข้า route เฉพาะ Manager (เช่น integrations) | ถูกปฏิเสธ (403 / redirect) |

---

*อัปเดตล่าสุด: สอดคล้องกับ validation ใน `RegisteredUserController`, `AuthenticatedSessionController` และ route `dashboard.index`.*
